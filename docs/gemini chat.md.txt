التحول من بناء تطبيق ملاحظات سحابي تقليدي إلى محرك ذاكرة سيادية موحدة (Agentic Memory Substrate) هو النقلة التي تجعل سياقك وهويتك البرمجية تنتقل معك تلقائياً داخل Cursor وClaude Code وتيرمنال النظام وأي بيئة Agent عبر بروتوكول MCP.
هذه هي المعمارية المقترحة لبناء MemoryNo SDK:
1. معمارية التخزين ونواة Turso (Edge & Vectors)
الاعتماد على Turso (libSQL) يمنحك ميزتين حاسمتين: العمل محلياً وعبر السحابة في نفس الوقت (Embedded Replicas)، مع دعم مدمج للفيكتور (vector32 / Cosine Similarity) للبحث الدلالي السريع دون الحاجة لخوادم إضافية.
مخطط عقدة الذاكرة (Memory Node Schema)
كل ذرة ذاكرة تُخزن كعقدة مستقلة مع مقاييس الاستدعاء:
CREATE TABLE memories (
    hash TEXT PRIMARY KEY,               -- SHA-256(content + type + created_at)
    type TEXT NOT NULL,                  -- 'note' | 'skill' | 'vault' | 'preference' | 'graph'
    title TEXT,
    content TEXT NOT NULL,               -- نص صريح أو Payload مشفر في حالة الـ Vault
    embedding F32_BLOB(768),             -- تمثيل فيكتوري دلالي للبحث السريع
    metadata JSONB DEFAULT '{}',         -- تفاصيل إضافية (أدوات المهارة، وسوم، روابط)
    linked_hashes JSONB DEFAULT '[]',    -- علاقات تشعبية مع ذكريات أخرى (Graph Links)
    recall_count INTEGER DEFAULT 0,      -- عدد مرات استدعاء هذه الذاكرة
    last_recalled_at INTEGER,            -- توقيت Unix لآخر استدعاء
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

-- فهرس فيكتوري دلالي
CREATE INDEX idx_memories_embedding ON memories(libsql_vector_idx(embedding));
-- فهرس للنوع وعدد مرات الاستدعاء
CREATE INDEX idx_memories_type_recall ON memories(type, recall_count DESC);

2. تصنيفات الذاكرة وسلوكها داخل النظام
 * ذاكرة الملاحظات (Raw / Note): أفكار ومسودات حرة تُفهرس فيكتورياً لتظهر فقط عند تشابه السياق الدلالي مع المحادثة الحالية.
 * ذاكرة التفضيلات والبيئة (Preferences / Env State): قواعد ثابتة يتم استرجاعها بحساسية عالية (مثل: تفضيل pm2 على Docker، منفذ 3333، الدومينات المحلية).
 * ذاكرة المهارات (Skills): خطوات إجرائية محددة بصيغة Agent Prompts أو أكواد أتمتة تُحقن كأدوات تنفيذية متى ما طُلب تنفيذ مهمة مطابقة.
 * ذاكرة العلاقات التشعبية (Graph Memory): حقل linked_hashes يربط الذكريات ببعضها؛ استدعاء عقدة معينة (مثلاً مشروع X) يرفع تلقائياً أوزان الذكريات المتصلة بها (المنفذ، المفاتيح الخاصة، المهارة المرتبطة).
 * عامل التعزيز (Reinforcement Weight): في كل مرة يستدعي فيها الـ Agent ذاكرة معينة، يزيد recall_count ويُحدث last_recalled_at، مما يعطي تلك الذاكرة أولوية أعلى عند تزاحم السياق (Context Window).
3. بروتوكول الخزنة المشفرة (Zero-Knowledge Vault)
لحفظ المفاتيح مثل key_gemini بأمان تام دون أن يطّلع عليها حتى السيرفر المستضيف لقاعدة Turso:
 * توليد مفتاح التشفير: تشتق مكتبة SDK مفتاح تشفير عالي القوة من كلمة مرورك المدخلة محلياً عبر خوارزمية Argon2id أو PBKDF2 مع Salt فريد خاص بكل مفتاح.
 * التشفير: يُشفر المفتاح عبر خوارزمية AES-256-GCM مع IV (Initialization Vector) عشوائي.
 * ما يُخزن في Turso:
   {
  "ciphertext": "a8fbc32...",
  "iv": "3d9e8...",
  "salt": "7f1b...",
  "tag": "e3b0..."
}

 * فك التشفير: عندما يطلب الـ Agent استخدام المفتاح، يُطلب منك إدخال كلمة المرور محلياً عبر الـ Terminal أو Prompt الـ MCP. يُفك التشفير في الذاكرة الحية (RAM) لتنفيذ العملية دون حفظ المفتاح بصيغة نصية في السجلات.
 * نقطة إعادة التشفير (Key Rotation): دالة داخل الـ SDK تستقبل old_password و new_password، تقوم بفك تشفير كل حقول vault وإعادة تشفيرها بالمفتاح الجديد دفعة واحدة.
4. واجهات الربط والتوزيع (SDK / MCP / Terminal)
أولاً: أداة الـ CLI والتثبيت الفوري
تشغيل الذاكرة في أي بيئة عمل جديدة بنقرة واحدة:
npx memoryno init --token=<YOUR_SYNC_TOKEN>

يقوم هذا الأمر بتهيئة ملف الإعدادات وإضافة السيرفر تلقائياً إلى ملفات إعداد Claude Code و Cursor (~/.cursor/mcp.json أو Claude Desktop).
ثانياً: أدوات خادم MCP (MemoryNo MCP Server)
يعرض الخادم لنموذج الذكاء الاصطناعي الأدوات التالية:
| اسم الأداة (MCP Tool) | الدور البرمجي | المدخلات الأساسية |
|---|---|---|
| recall_memory | جلب الذكريات بالبحث الدلالي أو النوع | query, type, limit, threshold |
| store_memory | حفظ معلومة، مهارة، أو تفضيل جديد مع بناء الفيكتور | content, type, title, tags, links |
| vault_store | تشفير مفتاح وتخزينه في الخزنة | key_name, secret_value, passphrase |
| vault_retrieve | استرجاع مفتاح وفك تشفيره لحظياً | key_name, passphrase |
| reinforce_memory | زيادة عداد الاستدعاء لعقدة محددة | hash |
5. تدفق المحادثة الحقيقي (Real-world Flow)
 * حالة التفضيلات والبيئة:
   حين تقول: "خزن أني أفضل PM2 على Docker، والمنفذ 3333 مخصص لـ test.domain.com"
   يستدعي الموديل فوراً:
   store_memory({
  "type": "preference",
  "title": "dev_env_preferences",
  "content": "يفضل المطور استخدام PM2 بدلاً من Docker. المنفذ 3333 مخصص للتجارب المرتبطة بـ test.domain.com.",
  "metadata": { "ports": [3333], "tools": ["pm2"], "domain": "test.domain.com" }
})

   عندما تطلب لاحقاً من Cursor: "شغل لي سيرفر تجريبي لتجربة واجهة معينة":
   يقوم Cursor تلقائياً باستدعاء recall_memory(query="تشغيل سيرفر تجريبي")، فيجد تفضيل المنفذ 3333 ومحرك PM2، ويشغل السيرفر وفق رغبتك دون أن تعيد تذكيره.
 * حالة المفاتيح المشفرة:
   حين تطلب: "خزن هذا المفتاح باسم key_gemini وكلمة السر @12345666":
   يقوم محرك الـ MCP بتشفير القيمة محلياً وتخزين الـ Payload المشفر مع نوع vault، ولا يمكن لأي Agent مستقبلاً قراءة القيمة الحقيقية إلا بعد استدعاء vault_retrieve وتمرير نفس كلمة السر.
بناء النواة كـ TypeScript Package مستقلة (@memoryno/core) مع خادم MCP مدمج يضمن لك تشغيلها مباشرة على أجهزتك السحابية أو المحلية، وربطها بسلاسة مع Claude Code، ومحررات البرمجة، والترمنال.
